Connect to your computer

Install Secpar on both devices. In the app, sign in to the same app account on both. The app account links your computers and friends. There is no login on this website. Select the computer you want to use and connect. Android connects to computers; it does not host.

To pair without an account, open Hosting → Pair a device on the host. Scan its code or paste its pairing link on the client.

Windows and Linux use one application for hosting and connecting. macOS is in development.

Stream menu

Click or tap the translucent triangle at the top left of the stream. It opens the controls in windowed and fullscreen views. Click outside the menu to close it.

Desktop controls include fullscreen, display selection when the host has several displays, audio details, help and disconnect. Android also has keyboard controls, trackpad mode and picture in picture.

Read the stream details

Resolution and frame rate show what the host negotiated. The decoder label shows the path actually producing video. Direct or Relay identifies the current connection route. Desktop network figures show round-trip delay, received bitrate and completed video frames per second. Android exposes its available timing figures under Stream stats.

A high received frame rate with choppy display points toward decoding or display work. A low received rate can also come from the host, packet loss or an idle desktop. Static screens do not need a constant stream of new frames.

Mouse and keyboard

Desktop: the mouse moves freely in a window. Fullscreen captures it. Move to the top-left menu to use local controls. Press Alt + F to switch between fullscreen and a window.

Android: a docked mouse stays free to leave the Secpar window. A connected keyboard works directly. Open the stream menu if you need the on-screen keyboard or want to use the phone as a trackpad.

Copy, cut and paste use Ctrl + C, Ctrl + X and Ctrl + V. Click the remote picture first if a local menu or text field has keyboard focus.

Share text

On the host, turn on Hosting → Share clipboard. On desktop clients, turn on Settings → Share text clipboard. Reconnect after changing client settings.

Copy text on one device and paste it on the other during the connection. Secpar does not replace the host clipboard with old client contents when a session starts. Clipboard changes received from the host are not echoed back.

Clipboard sharing currently transfers text up to 1 MB. Copying files or images through the clipboard is not supported by the desktop clients.

Choppy video or silent audio

On Linux, open the stream menu and select Decoder → Software. If this fixes playback, the hardware path is the problem. Automatic checks decode time during the actual stream and switches to software when the native decoder repeatedly falls behind.

Lower resolution or frame rate if decoding still cannot keep up. Lower the bitrate if the connection cannot carry the stream.

Linux audio follows the desktop PulseAudio or PipeWire sound service, with ALSA as a fallback. Check the selected speakers in the desktop volume panel. Open Audio in the stream menu if sound is missing. The packet and decoder counters help show whether audio reaches the client.

Host from KDE Wayland

Keep the Linux computer signed in to its desktop session. Connect from another device, then select a monitor and allow keyboard and pointer access in KDE's sharing dialog.

If the client disconnects after consent, copy the error shown above its computer list. The portal can grant access before an encoder, PipeWire stream or audio source fails. An optional audio-source error should leave video connected.

Linux hosting currently uses LAN connections. Remote Linux hosting is still being added. A headless OMV server is not a substitute for a logged-in KDE desktop session.

Connection routes

For computers on your account, Secpar tries the saved LAN addresses first. Windows hosts with Connect anywhere can use the relay when a direct control connection is unavailable. Streaming tries authenticated direct UDP; TURN carries media when direct routing fails.

Gigabit internet does not guarantee a low-delay route. Test both devices on Ethernet when possible. On office networks, UDP filtering or an enforced relay can affect streaming even when downloads are fast.

Updates and errors

Open Check for updates in the app. Download becomes available when there is a newer package for that device. Installing a Windows host update can interrupt connected clients.

For a failed connection, use Copy error. For audio, use Copy details in the stream menu. Share the app version, host and client operating systems, and the step that failed. Keep account credentials and pairing links private.
